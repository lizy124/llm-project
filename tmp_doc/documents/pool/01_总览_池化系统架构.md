# vllm-ascend 池化系统架构总览（以 Mooncake 为例）

## 1. 背景与目标

在 LLM 推理中，KV Cache 是显存占用的主要来源。为了避免重复计算，vllm-ascend 实现了一套池化系统，将 KV Cache 存储到外部共享存储（如 Mooncake 分布式 KV Store），使得：

- **不同请求之间**可以复用相同前缀的 KV Cache（前缀缓存）
- **P/D 分离场景**（Prefill/Decode 分离）中，Prefill 节点计算出的 KV Cache 可以传输给 Decode 节点直接使用
- 支持 **CPU 内存 / SSD** 作为 KV Cache 的后备存储

## 3. 两大架构路径

vllm-ascend 提供了两种主要的 KV Cache 池化/传输路径：

| 路径 | 连接器名称 | 适用场景 | 底层存储 |
|------|-----------|---------|---------|
| **AscendStore** | `AscendStoreConnector` | 通用 KV Cache 池化、前缀缓存复用 | Mooncake Distributed Store（CPU/SSD） |
| **P2P** | `MooncakeConnector` | P/D 分离（Prefill 节点直接传 KV 到 Decode 节点） | Mooncake TransferEngine（RDMA/NPU Direct） |

本文档以 **AscendStore + Mooncake Backend** 为主要分析对象，因为它是最完整的池化系统实现，涵盖了 "存" 和 "取" 的完整生命周期。

## 5. 核心数据流

### 5.1 "存 KV Cache" 流程（一句话概括）

Scheduler 决定哪些请求的 KV Cache 需要保存 → Worker 后台线程将 NPU 显存中的 KV Cache 数据通过 Mooncake Store 写入 CPU/SSD 存储。

### 5.2 "取 KV Cache" 流程（一句话概括）

Scheduler 查询外部池中是否有匹配的 KV Cache → 如果有，预留本地 block → Worker 后台线程从 Mooncake Store 读取数据并写入本地 NPU 显存。

### 5.3 关键角色

| 角色 | 组件 | 职责 |
|------|------|------|
| **kv_producer** | SendingThread | 负责将 KV Cache 存入外部池 |
| **kv_consumer** | RecvingThread | 负责从外部池加载 KV Cache |
| **kv_both** | 两者都有 | 既存又取 |
