# 01 — KV 池逐层保存：需求与方案归档

归档日期：2026-10-24；覆盖 10-22～24 的本地留存记录，最新现场采样截至 10-24 10:24:53。本归档是阶段性快照，验证结论为部分通过；归档完成不代表全部故障解决。本次未连接服务器或改变服务。

## 1. 需求、背景与边界

需求是在 AscendStoreConnector（memcache、layerwise 保存）发生故障时，定位首发原因，恢复正确的累计块表维护，并避免进程退出及块/key 错配。

最初观察到 `KVCacheStoreLayerSendingThread` 等待事件超时，随后另有 `ReqMeta GVA metadata does not cover requested block range`。两者首发原因和调用位置不同，任务因此采用稳定名称 `KVPoolLayerwiseSave`，按故障类型分别验收。

| 范围 | 目标 |
|---|---|
| GVA 元数据 | 保存范围、累计计算进度、累计块表的绝对位置一致 |
| 正常路径 | 不因止血判定误跳过正常保存；池读写与命中仍有效 |
| 抢占恢复 | V2 恢复后下一步普通增量正常追加，不能替换完整表 |
| 稳定性 | 同一版本、目标场景触发后，无 GVA fatal；结合请求成功、写入、精度验收 |
| 设备事件 | 独立保留证据及缺口，本归档不宣称其根因已解决 |

## 2. 失败机制与代码缺陷

保存端按请求绝对块号访问数组。例如保存终点 28672 token，group0 块大小 128，对应 `[0,224)`。run C 实测数组却只有 63 项，后续变为 127。224 是需支持访问的逻辑位置数，不等于必须搬运全部 224 块；已提交 keys、掩码、零 GVA 会减少实际传输。

普通 running 步的增量必须先追加到累计块表。直接将终点 224 改成 63，或只填长数组，都不能恢复块身份及绝对位置映射。数组足够长时仍可能错配 key，这一风险不能靠覆盖断言排除。

后续源码路径定位到 MRV2：

```text
抢占：记录 _preempted_req_ids，删除旧 tracker
→ V2 恢复：以 NewRequestData 经 new 分支建立完整表
→ 旧抢占标记未清除
→ 下一步 RUNNING 增量误入 preempted handler
→ 以增量重建 tracker，保存游标置 0，替换完整累计表
→ 绝对保存范围索引短表，触发断言或块/key 错配风险
```

源码缺陷与 logs_C 冻结数组形态相符，已有 mock 与本地修复采样支持。但历史目标请求缺少恢复入口表、marker 和覆盖前 tracker 的完整记录，不能表述为每一步均现场实测。

## 3. 方案演进与选定路线

| 路线 | 做法与取舍 | 留存状态 |
|---|---|---|
| 窗口对齐（#19517 相关） | 显式记录每组 base，调整 range、数组、keys、游标 | 早期实现因全表来源、连续性及逐组语义问题冻结，未作为已验证方案 |
| 保存闸门（#19533 相关） | 对 WINDOW/UNPROVABLE 跳过保存，保留 worker 断言 | 止血 v3 已现场验证；代价是受影响请求少写缓存 |
| V2 标记生命周期（#19567 相关） | 在 V2 new 分支消费旧抢占标记，避免下一步错误重建 | 根因修复方向明确；纯 PR head 与 worker 全链路验收不足 |

后续根因修复采用生命周期路线；保存闸门作为已验证的保守止血历史单独记录。不能将两种实现、采样和长稳时长混成同一版本的成绩。当前归档不重新选择服务器部署版本。

根因修复未增加面向最终用户的配置项；代码受 `use_v2_model_runner` 门控，保持 MRV1 原有恢复路径。恢复步从 0 重新检查缺失 keys，随后正常推进；“继承旧保存进度”不是现有测试实际观察到的行为。

## 4. 约束、兼容性与风险

- vLLM/vLLM-Ascend 必须配对；早期基线为 v0.30.0 / Ascend `06b685f346`，vLLM 精确源码 SHA 和镜像 digest 未完整留存。
- 现场已有传输失败隔离，不能用本地 main 整文件覆盖 release 代码；GVA 断言发生在传输线程隔离范围外。
- `Request` 与 `NewRequestData` 字段不同；准入快照在无外部命中时可为空，不可作为通用全表。
- 止血 v1 曾将正常请求全判 UNPROVABLE，出现 1832 次跳过、写池停摆；fatal=0 不能替代功能判定。
- layerwise snapshot、partial、async-load、released 请求与在途保存隔离仍需特定覆盖。
- 不上传、不 push；详细日志和源码快照外置到本地 data；本次没有读取、解析或上传图片。
