# 第 2 章：连接器注册与角色分发

## 2.1 连接器工厂注册

所有 KV 连接器通过 vLLM 的 `KVConnectorFactory` 注册。在 [register_connector()](../../code/vllm-ascend/vllm_ascend/distributed/kv_transfer/__init__.py) 函数中完成注册。

### 为什么需要注册机制？

vLLM 是一个**通用推理框架**，需要支持多种硬件平台（NVIDIA GPU、AMD GPU、华为 NPU 等）。上游无法为每个硬件平台写代码，所以设计工厂模式：

- **上游只定义 `KVConnectorBase_V1` 接口规范**：规定连接器必须实现哪些方法（如 `get_num_new_matched_tokens`、`start_load_kv`、`wait_for_save` 等）
- **各硬件厂商实现自己的连接器**：vllm-ascend（华为 NPU）、vllm-amd（AMD GPU）等根据各自硬件特性实现接口
- **通过注册机制"告诉"上游有哪些实现可用**：厂商在插件初始化时调用 `register_connector()`，将实现类注册到工厂

这实现了 **"接口在上游，实现在下游"** 的分层架构：

```
┌─────────────────────────────────────────┐
│  vLLM upstream                          │
│  ├── KVConnectorBase_V1 (接口规范)       │
│  ├── KVConnectorFactory (工厂)          │
│  └── Scheduler/Worker (调用者)          │
└─────────────────────────────────────────┘
                    ↓ 实现接口
┌─────────────────────────────────────────┐
│  vllm-ascend (华为 NPU 适配)            │
│  ├── AscendStoreConnector               │
│  ├── MooncakeConnector                  │
│  └── register_connector() → 注册        │
└─────────────────────────────────────────┘
```

```python
# vllm_ascend/distributed/kv_transfer/__init__.py
def register_connector():
    # 覆盖上游 MultiConnector，使用 AscendMultiConnector
    if "MultiConnector" in KVConnectorFactory._registry:
        KVConnectorFactory._registry.pop("MultiConnector")
    KVConnectorFactory.register_connector(
        "MultiConnector",
        "vllm_ascend.distributed.kv_transfer.ascend_multi_connector",
        "AscendMultiConnector",
    )

    # 注册 Mooncake P2P 路径
    KVConnectorFactory.register_connector(
        "MooncakeConnectorV1",
        "vllm_ascend.distributed.kv_transfer.kv_p2p.mooncake_connector",
        "MooncakeConnector",
    )
    KVConnectorFactory.register_connector(
        "MooncakeHybridConnector",
        "vllm_ascend.distributed.kv_transfer.kv_p2p.mooncake_hybrid_connector",
        "MooncakeConnector",
    )
    KVConnectorFactory.register_connector(
        "MooncakeLayerwiseConnector",
        "vllm_ascend.distributed.kv_transfer.kv_p2p.mooncake_layerwise_connector",
        "MooncakeLayerwiseConnector",
    )

    # 注册 AscendStore 池化路径
    KVConnectorFactory.register_connector(
        "MooncakeConnectorStoreV1",  # 旧名称，保留兼容
        "vllm_ascend.distributed.kv_transfer.kv_pool.ascend_store.ascend_store_connector",
        "AscendStoreConnector",
    )
    KVConnectorFactory.register_connector(
        "AscendStoreConnector",  # 新名称，推荐使用
        "vllm_ascend.distributed.kv_transfer.kv_pool.ascend_store.ascend_store_connector",
        "AscendStoreConnector",
    )

    # 其他 KV pool / offload 连接器
    KVConnectorFactory.register_connector(
        "UCMConnector",
        "vllm_ascend.distributed.kv_transfer.kv_pool.ucm_connector",
        "UCMConnectorV1",
    )
    KVConnectorFactory.register_connector(
        "LMCacheAscendConnector",
        "vllm_ascend.distributed.kv_transfer.kv_pool.lmcache_ascend_connector",
        "LMCacheConnectorV1",
    )

    # 如果上游存在 SimpleCPUOffloadConnector，则覆盖为 NPU 适配实现
    KVConnectorFactory.register_connector(
        "SimpleCPUOffloadConnector",
        "vllm_ascend.distributed.kv_transfer.kv_pool.simple_cpu_offload.simple_cpu_offload_connector",
        "AscendSimpleCPUOffloadConnector",
    )
```

> 注：`SimpleCPUOffloadConnector` 的覆盖是条件执行的，只有当前 vLLM 版本存在上游 `vllm.v1.simple_kv_offload` 模块时才注册。

### 注册关系表

| 配置名称 | 实现类 | 路径 |
|---------|--------|------|
| `MultiConnector` | `AscendMultiConnector` | kv_transfer → ascend_multi_connector |
| `AscendStoreConnector` | `AscendStoreConnector` | kv_pool → ascend_store |
| `MooncakeConnectorStoreV1` | `AscendStoreConnector` | （同上，旧名称） |
| `MooncakeConnectorV1` | `mooncake_connector.MooncakeConnector` | kv_p2p → mooncake_connector |
| `MooncakeHybridConnector` | `mooncake_hybrid_connector.MooncakeConnector` | kv_p2p → mooncake_hybrid_connector |
| `MooncakeLayerwiseConnector` | `MooncakeLayerwiseConnector` | kv_p2p → mooncake_layerwise_connector |
| `UCMConnector` | `UCMConnectorV1` | kv_pool → ucm_connector |
| `LMCacheAscendConnector` | `LMCacheConnectorV1` | kv_pool → lmcache_ascend_connector |
| `SimpleCPUOffloadConnector` | `AscendSimpleCPUOffloadConnector` | kv_pool → simple_cpu_offload（条件覆盖） |

## 2.2 AscendStoreConnector：Scheduler/Worker 分离

[`AscendStoreConnector`](../../code/vllm-ascend/vllm_ascend/distributed/kv_transfer/kv_pool/ascend_store/ascend_store_connector.py) 继承自 `KVConnectorBase_V1` 并实现了 `SupportsHMA`（支持混合 Attention 的 KV Cache 组）。

### 2.2.1 初始化分支逻辑

```python
class AscendStoreConnector(KVConnectorBase_V1, SupportsHMA):
    def __init__(self, vllm_config, role, kv_cache_config=None):
        # 根据 role 不同，创建不同的内部组件
        if role == KVConnectorRole.SCHEDULER:
            # Scheduler 端：创建 KVPoolScheduler
            self.connector_scheduler = KVPoolScheduler(
                vllm_config, self.use_layerwise, kv_cache_config
            )
        else:
            # Worker 端：创建 KVPoolWorker
            self.connector_worker = KVPoolWorker(
                vllm_config, self.use_layerwise, kv_cache_config
            )
            # 仅在 rank 0 上启动 LookupKeyServer（ZMQ REP 服务端）
            if vllm_config.parallel_config.rank == 0:
                self.lookup_server = LookupKeyServer(
                    self.connector_worker, vllm_config, self.use_layerwise
                )
```

### 2.2.2 关键配置参数

从 `vllm_config.kv_transfer_config.kv_connector_extra_config` 中读取：

| 参数 | 含义 | 默认值 |
|------|------|--------|
| `backend` | 后端类型 | `"mooncake"` |
| `use_layerwise` | 是否逐层传输 | `False` |
| `load_async` | 是否异步加载 KV Cache | `False` |
| `consumer_is_to_put` | Consumer 是否也执行 put | `False` |
| `consumer_is_to_load` | Consumer 是否执行 load | `False` |
| `discard_partial_chunks` | 是否丢弃不完整的 chunk | `True` |
| `lookup_rpc_port` | Lookup 服务的 RPC 端口 | 同 mooncake_rpc_port |

### 2.2.3 Scheduler 端方法代理

所有 Scheduler 端方法直接代理到 `KVPoolScheduler`：

```python
def get_num_new_matched_tokens(self, request, num_computed_tokens):
    return self.connector_scheduler.get_num_new_matched_tokens(request, num_computed_tokens)

def update_state_after_alloc(self, request, blocks, num_external_tokens):
    return self.connector_scheduler.update_state_after_alloc(request, blocks, num_external_tokens)

def build_connector_meta(self, scheduler_output):
    return self.connector_scheduler.build_connector_meta(scheduler_output)
```

### 2.2.4 Worker 端方法代理

```python
def register_kv_caches(self, kv_caches):
    self.connector_worker.register_kv_caches(kv_caches)

def start_load_kv(self, forward_context, **kwargs):
    metadata = self._get_connector_metadata()
    self.connector_worker.start_load_kv(metadata)

def wait_for_save(self):
    self.connector_worker.wait_for_save(self._get_connector_metadata())
```

## 2.3 角色分发总结

```
                    AscendStoreConnector
                           │
                    role == ?
                    ┌──────┴──────┐
                    ▼              ▼
              SCHEDULER         WORKER
                    │              │
              KVPoolScheduler   KVPoolWorker
              ┌─────────────┐   ┌──────────────────┐
              │LookupKeyClient│   │ register_kv_caches│
              │调度决策逻辑    │   │ start_load_kv     │
              │构建元数据      │   │ wait_for_save     │
              └─────────────┘   │ save_kv_layer     │
                                │ lookup()          │
                                │ 后台传输线程       │
                                └──────────────────┘
```

这种设计将调度决策（Scheduler 进程）和 I/O 执行（Worker 进程）完全解耦，符合 vLLM 的 Scheduler/Worker 分离架构。
