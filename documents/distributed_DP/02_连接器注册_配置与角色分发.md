# 第 2 章：连接器注册、配置与角色分发

## 2.1 注册入口

P/D 分离相关连接器通过 `vllm_ascend.distributed.kv_transfer.register_connector()` 注册到 vLLM 的 `KVConnectorFactory`。

```python
# code/vllm-ascend/vllm_ascend/distributed/kv_transfer/__init__.py
def register_connector():
    KVConnectorFactory.register_connector(
        "MooncakeConnectorV1",
        "vllm_ascend.distributed.kv_transfer.kv_p2p.mooncake_connector",
        "MooncakeConnector",
    )

    KVConnectorFactory.register_connector(
        "MooncakeHybridConnector",
        "vllm_ascend.distributed.kv_transfer.kv_p2p.mooncake_hybrid_connector",
        "MooncakeConnector",
    )

    KVConnectorFactory.register_connector(
        "MooncakeLayerwiseConnector",
        "vllm_ascend.distributed.kv_transfer.kv_p2p.mooncake_layerwise_connector",
        "MooncakeLayerwiseConnector",
    )
```

注册关系：

| 配置名称 | 模块 | 类 | 说明 |
|---------|------|----|------|
| `MooncakeConnectorV1` | `kv_p2p.mooncake_connector` | `MooncakeConnector` | 当前标准 P/D pull 路径 |
| `MooncakeHybridConnector` | `kv_p2p.mooncake_hybrid_connector` | `MooncakeConnector` | 旧/兼容 hybrid 路径，结构类似标准 connector |
| `MooncakeLayerwiseConnector` | `kv_p2p.mooncake_layerwise_connector` | `MooncakeLayerwiseConnector` | Layerwise push 路径 |

## 2.2 典型配置

离线示例位于 `code/vllm-ascend/examples/offline_disaggregated_prefill_npu.py`。

Prefill 节点：

```python
KVTransferConfig(
    kv_connector="MooncakeConnectorV1",
    kv_role="kv_producer",
    kv_port="30000",
    engine_id="0",
    kv_connector_extra_config={
        "prefill": {"dp_size": 1, "tp_size": 1},
        "decode": {"dp_size": 1, "tp_size": 1},
    },
)
```

Decode 节点：

```python
KVTransferConfig(
    kv_connector="MooncakeConnectorV1",
    kv_role="kv_consumer",
    kv_port="30100",
    engine_id="1",
    kv_connector_extra_config={
        "prefill": {"dp_size": 1, "tp_size": 1},
        "decode": {"dp_size": 1, "tp_size": 1},
    },
)
```

关键字段：

| 字段 | 含义 |
|------|------|
| `kv_connector` | 选择 P/D 连接器，标准 pull 用 `MooncakeConnectorV1` |
| `kv_role` | `kv_producer` 表示 P 节点，`kv_consumer` 表示 D 节点 |
| `kv_port` | side-channel 握手端口基址；每个 rank 会在基址上加 rank offset |
| `engine_id` | 当前 engine 的唯一 ID，远端 metadata 会用它区分 P/D engine |
| `prefill.tp_size/dp_size/pp_size` | P 侧并行配置摘要，用于 D 侧计算要拉哪些 P rank |
| `decode.tp_size/dp_size/pp_size` | D 侧并行配置摘要，用于 rank/block 映射 |
| `prefill.pp_layer_partition` | 可选，P 侧 PP 每段层数；D 侧据此定位每个 P PP rank 的层范围 |

## 2.3 顶层类：MooncakeConnector

`MooncakeConnector` 同时实现 Scheduler 端和 Worker 端接口，内部根据 `role` 分发：

```python
class MooncakeConnector(KVConnectorBase_V1, SupportsHMA):
    def __init__(self, vllm_config, role, kv_cache_config=None):
        self.engine_id = vllm_config.kv_transfer_config.engine_id
        self._connector_metadata = MooncakeConnectorMetadata()

        if role == KVConnectorRole.SCHEDULER:
            self.connector_scheduler = MooncakeConnectorScheduler(
                vllm_config, str(self.engine_id), kv_cache_config
            )
            self.connector_worker = None
        elif role == KVConnectorRole.WORKER:
            self.connector_scheduler = None
            self.connector_worker = MooncakeConnectorWorker(
                vllm_config, str(self.engine_id), kv_cache_config
            )
```

### Scheduler 端代理方法

```python
def get_num_new_matched_tokens(self, request, num_computed_tokens):
    return self.connector_scheduler.get_num_new_matched_tokens(request, num_computed_tokens)

def update_state_after_alloc(self, request, blocks, num_external_tokens):
    return self.connector_scheduler.update_state_after_alloc(request, blocks, num_external_tokens)

def build_connector_meta(self, scheduler_output):
    return self.connector_scheduler.build_connector_meta(scheduler_output)

def request_finished(self, request, block_ids):
    return self.connector_scheduler.request_finished(request, (block_ids,))

def request_finished_all_groups(self, request, block_ids):
    return self.connector_scheduler.request_finished(request, block_ids)
```

### Worker 端代理方法

```python
def register_kv_caches(self, kv_caches):
    self.connector_worker.register_kv_caches(kv_caches)

def start_load_kv(self, forward_context, **kwargs):
    self.connector_worker.start_load_kv(self._connector_metadata)

def get_finished(self, finished_req_ids):
    return self.connector_worker.get_finished()

def get_block_ids_with_load_errors(self):
    return self.connector_worker.get_block_ids_with_load_errors()
```

标准 `MooncakeConnector` 不在 attention layer 中显式 `save_kv_layer()`，也不需要 `wait_for_layer_load()`；它的 KV 传输由 D 侧 `start_load_kv()` 触发后台 pull 完成。

## 2.4 握手 metadata 接口

Worker 初始化并注册 KV Cache 后，会生成 `MooncakeAgentMetadata`：

```python
class MooncakeAgentMetadata(msgspec.Struct, omit_defaults=True, dict=True):
    engine_id: str
    te_rpc_port: int
    kv_group2layeridx: dict[int, tuple[dict[str, Any], list[int]]]
    block_size: int
    kv_caches_base_addr: list[list[int]]
    block_size_scale: list[list[int]]
    num_blocks: int
    block_lens: list[list[int]]
    block_strides: list[list[int]]
    local_ip: str = ""
```

顶层连接器通过：

```python
def get_handshake_metadata(self):
    return self.connector_worker.xfer_handshake_metadata

def set_xfer_handshake_metadata(self, metadata):
    self.connector_scheduler.set_xfer_handshake_metadata(metadata)
```

把 worker metadata 回传给 scheduler。Scheduler 端保存为 `multi_nodes_meta_mapping`，用于跨节点场景中根据 rank 找到对应 host / engine_id。

## 2.5 side-channel 端口计算

标准 `MooncakeConnector` 的 side-channel 基址：

```python
self.side_channel_port = (
    kv_port
    + data_parallel_rank * tensor_parallel_size * pipeline_parallel_size * pcp_size
)
```

Worker rank 的握手端口：

```python
device_index = (pp_rank + pcp_rank) * tp_size + tp_rank
self.handshake_port = self.side_channel_port + device_index
```

P 侧 `KVCacheSendingThread` 会在对应端口上创建 ZMQ `ROUTER` socket，处理 D 侧的 `GET_META_MSG` 和 `DONE_RECVING_MSG`。

## 2.6 角色分发表

| 角色 | Scheduler 行为 | Worker 行为 |
|------|----------------|-------------|
| `kv_producer` | prefill 完成时 `request_finished()` 返回 remote KV 信息；延迟释放 blocks | 启动 `KVCacheSendingThread`，监听 metadata 查询和完成确认 |
| `kv_consumer` | `get_num_new_matched_tokens()` 识别 `do_remote_prefill`，预分配本地 blocks | 启动 `KVCacheRecvingThread`，从 P 节点拉取 KV 到本地 KV Cache |

## 2.7 Proxy 注入的 kv_transfer_params

典型在线代理逻辑参考上游 `code/vllm/examples/disaggregated/mooncake_connector/mooncake_connector_proxy.py`。

发给 P 节点时：

```python
req_data["kv_transfer_params"] = {
    "do_remote_decode": True,
    "do_remote_prefill": False,
    "transfer_id": f"xfer-{request_id}",
}
req_data["max_tokens"] = 1
```

发给 D 节点时：

```python
req_data["kv_transfer_params"] = {
    "do_remote_decode": False,
    "do_remote_prefill": True,
    "remote_engine_id": ...,
    "remote_block_ids": ...,
    "remote_host": ...,
    "remote_port": ...,
    "remote_ptp_size": ...,
}
```

`do_remote_decode=True` 表示“这是发给 P 节点的 prefill 请求，完成后要把 KV 暴露给远端 decode”；`do_remote_prefill=True` 表示“这是发给 D 节点的 decode 请求，需要先从远端拉取 prefill KV”。
